# Deploying PayRaider on Render

`render.yaml` at the repository root is a Render Blueprint. Applying it
creates four services:

| Service | What it is | Plan |
| --- | --- | --- |
| `payraider-api` | The backend (Docker), with a 1 GB disk for its SQLite database | Starter (paid): a persistent disk needs a paid instance |
| `payraider-redis` | Redis for wallet sign-in sessions and rate limits | Free |
| `payraider-mcp` | The hosted MCP plugin server | Free |
| `payraider-web` | The Next.js web app | Free |

Free Render services sleep when idle and take a few seconds to wake up. That
is fine for a demo; move the API off the free tier before real traffic.

## 1. Apply the Blueprint

1. Sign in at render.com and connect your GitHub account.
2. **New > Blueprint**, pick `Ndifreke000/stellar-insights`, branch `main`.
3. Render lists the four services and asks for the variables marked
   `sync: false`. Fill them in as below, then **Apply**.

## 2. Variables Render asks for

You will not know the service URLs until the first deploy finishes. Enter a
placeholder for those, then come back and set the real values (step 3).

| Service | Variable | Value |
| --- | --- | --- |
| `payraider-api` | `STELLAR_RPC_URL_MAINNET` | A Soroban RPC URL for mainnet from an RPC provider |
| | `ENCRYPTION_KEY` | Output of `openssl rand -hex 32` (exactly 64 hex characters) |
| | `SEP10_SERVER_PUBLIC_KEY` | A Stellar public key (`G...`) you control. Only the public key is needed |
| | `SEP10_HOME_DOMAIN` | The web app's host name, e.g. `payraider-web.onrender.com` |
| | `CORS_ALLOWED_ORIGINS` | The web app's origin, e.g. `https://payraider-web.onrender.com` |
| | `PAYRAIDER_TREASURY_ACCOUNT` | Your Stellar account for plan payments, or empty to keep everything free |
| `payraider-mcp` | `PAYRAIDER_BASE_URL` | The API's URL, e.g. `https://payraider-api.onrender.com` |
| `payraider-web` | `NEXT_PUBLIC_API_URL` | The API's URL, e.g. `https://payraider-api.onrender.com` |

`JWT_SECRET` and `PAYRAIDER_MCP_AUTH_TOKEN` are generated by Render. Read the
MCP token from the `payraider-mcp` service's Environment tab; plugin clients
send it as `Authorization: Bearer <token>`.

`SEP10_HOME_DOMAIN` must equal the host name people use to open the web app.
Wallet sign-in sends that host name and the API rejects any other.

## 3. After the first deploy

1. Copy each service's URL from the Render dashboard.
2. Set `SEP10_HOME_DOMAIN`, `CORS_ALLOWED_ORIGINS`, `PAYRAIDER_BASE_URL` and
   `NEXT_PUBLIC_API_URL` to the real URLs if you used placeholders.
   `NEXT_PUBLIC_API_URL` is compiled into the web app, so redeploy
   `payraider-web` after changing it.
3. Check it works:

   ```bash
   curl https://payraider-api.onrender.com/health
   curl "https://payraider-api.onrender.com/api/v1/preflight?source_asset=USDC&destination_asset=XLM"
   curl https://payraider-mcp.onrender.com/healthz
   ```

## Other hosts

The API and MCP server are plain Docker images:

```bash
docker build -t payraider-api backend
docker run -p 8080:8080 -v payraider-data:/data --env-file backend/.env payraider-api

docker build -f sdk/mcp-server/Dockerfile -t payraider-mcp sdk
```

The API image keeps its database at `/data/payraider.db`; mount a volume
there. It listens on `$PORT` if the host sets one, otherwise 8080.
