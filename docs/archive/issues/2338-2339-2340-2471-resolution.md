## #2471 — Database backup verification failing

`docs/backup-system.md` now documents the full restore procedure referenced by
the backup-verification CI workflow, covering:

- All `BACKUP_*` environment variables and their defaults
- Step-by-step manual restore (stop service → swap file →
  `PRAGMA integrity_check` → restart → health-check)
- How the automated CI restore-verification job works and what to do when it
  reports a failure
- Retention policy and troubleshooting table

## #2339 — Forbidden require() imports in frontend

`frontend/eslint.config.mjs` now enforces:

- `@typescript-eslint/no-unused-vars: warn` with `_`-prefix escape hatch
- `no-unused-vars: off` (avoids double-reporting on TypeScript files)
- `@typescript-eslint/no-require-imports: error` in all non-script files
- `@typescript-eslint/no-require-imports: off` scoped to `scripts/**/*.js`
  (plain Node CJS scripts that cannot use ESM)

## #2338 — Database pool uses default settings

`PoolConfig::from_env()` is implemented in `backend/src/database.rs`, called
in `main.rs` at startup, logged by `env_config.rs`, and all five knobs are
documented in `backend/.env.example`:

- `DB_POOL_MAX_CONNECTIONS`
- `DB_POOL_MIN_CONNECTIONS`
- `DB_POOL_CONNECT_TIMEOUT_SECONDS`
- `DB_POOL_IDLE_TIMEOUT_SECONDS`
- `DB_POOL_MAX_LIFETIME_SECONDS`
